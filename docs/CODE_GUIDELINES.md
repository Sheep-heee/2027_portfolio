# 코드 작성·커스텀·인수 규칙

목표: 사용자가 코드를 읽고 직접 수정할 수 있으며, AI가 변경 범위와 이유를 이해할 수 있게 한다. 2026-10-02 선택에 따라 Next.js/TypeScript와 Sanity Free 기반 로컬 골격을 2026-10-08부터 작성한다. Cloudflare 배포 어댑터는 아직 미정이다.

## 기본 원칙

- 기능별로 명확히 분리하되 작은 기능을 지나치게 추상화하지 않는다.
- 페이지는 조합, 컴포넌트는 표시·상호작용, 서비스 모듈은 데이터·외부 연동을 담당한다.
- TypeScript strict, 불명확한 any 제한, 외부 데이터는 경계에서 검증.
- 이름·메뉴·소개·프로젝트·연락처를 화면 코드에 직접 넣지 않는다.
- 서비스 SDK 호출을 여러 화면에 흩뿌리지 않는다. 교체 가능한 조회·저장 경계 제공.
- 의존성 최소화. 추가 시 필요성과 대안을 결정 기록에 남긴다.
- 코드 자체보다 제약·선택 이유를 주석으로 설명. 사용하지 않는 코드와 추측 기반 기능 금지.

## 권장 폴더 책임

```text
src/
  app/                 # 라우트·페이지 조합·서버 진입점
  components/ui/       # 재사용 UI
  components/layout/   # 헤더·푸터·컨테이너
  features/projects/   # 목록·상세·필터
  features/contact/    # 폼과 처리 흐름
  blocks/              # 블록 타입·렌더러·편집 연결
  content/             # 콘텐츠 모델·조회 경계
  services/            # CMS·메일·저장소 연동
  i18n/                # locale·UI 사전
  styles/              # 토큰·폰트·초기화
  fixtures/            # 검토용 테스트 데이터
```

실제 프레임워크 관례에 맞춰 변경 가능. 미리 빈 디렉터리나 가짜 구현을 만들 필요는 없다.

## 스타일과 UI

- 확정 CSS 규칙: `html { font-size: 16px; }`, 기본 본문 `1rem`. 글자·여백·gap·높이·아이콘 등 크기는 rem을 사용한다. 비율(%), vw 기반 유동 크기, 뷰포트 높이, 단위 없는 행간은 용도에 맞게 유지한다.
- px 예외는 content width(컨테이너·읽기 폭·검토 화면 폭), border 두께, breakpoint다. 루트 16px 설정은 기준 정의를 위한 예외다. SVG viewBox·도형 좌표는 CSS 길이 변환 대상이 아니다.
- KoddiUD는 400=Regular.woff2, 500=Bold.woff2, 700=ExtraBold.woff2로 각각 @font-face 지정한다. Regular에 두꺼운 weight 범위를 선언하거나 합성 굵기를 쓰지 않는다. `font-synthesis: none`을 적용한다. 800 등 미등록 굵기는 쓰지 않는다.
- 위 KoddiUD 숫자 매핑은 Montserrat에 그대로 적용하지 않는다. Montserrat는 해당 파일의 실제 400/700 매핑을 유지한다.
- KoddiUD의 파일 선택을 명시하기 위해 패밀리를 `KoddiRegular` / `KoddiBold` / `KoddiExtraBold`로 분리한다. 본문은 Regular+400, 일반 제목 h1/h2/h3는 Bold+500, 홈 큰 이름은 ExtraBold+700을 직접 지정한다. weight 숫자만 바꾸지 않는다. 자유 블록에도 같은 규칙을 적용한다.
- 폰트 검증은 computed weight만으로 완료하지 않는다. computed family와 해당 @font-face의 src, 폰트 로드 상태까지 확인한다.
- 사용자 실측 제한: KoddiBold(500)는 **정확히 1.5rem(24px) 또는 1.875rem(30px) 이상**에서만 사용한다. 20px대의 다른 크기와 24px 미만에는 사용하지 않는다. 해당 범위의 제목은 안정적인 크기로 조정하고 작은 메뉴·필터·보조 정보는 Regular(400)를 사용한다. 강조는 선·간격·표시 상태로 보완한다.
- KoddiBold에는 24~30px 사이를 통과하는 clamp/vw 유동 크기를 적용하지 않는다. 24px 고정 또는 최솟값 30px 이상의 크기를 사용한다. 이 결과는 사용자의 현재 환경 테스트이며 ExtraBold·Montserrat에 동일 제한을 추정해 적용하지 않는다.

- CSS Modules 우선 제안. 전역 CSS는 reset·폰트·토큰에 제한.
- 색·서체·간격·최대 너비·반응형 기준의 단일 정의. 임의 숫자 반복을 줄인다.
- 기본 블록은 공통 토큰을 따르고 자유 블록은 격리 문서에 승인된 토큰을 전달.
- 의미 있는 HTML·제목 순서·입력 label·키보드 접근을 기본으로 한다.
- 공개 제목·본문의 고정 높이와 무조건 생략 금지. 긴 문구·이미지 비율 변화 지원.
- 테스트용 표시는 운영 빌드에서 혼입되지 않게 검증.

## 서버·데이터·보안

- 비밀키는 서버 전용 환경변수. 브라우저 번들·문서·로그에 노출 금지.
- 공개·초안·언어 상태를 서버에서 검사. UI 숨김만으로 권한을 처리하지 않는다.
- 자유 코드 원본 보존과 안전한 렌더링을 분리. 실행 권한은 별도 정책.
- 안정적인 ID와 schema 버전 사용. 구조 변경 시 migration·복구 절차 기록.
- 문의 저장·알림·전달 상태와 재시도를 명시적으로 모델링.
- 개인정보를 공개 CMS 데이터셋·공유 캐시·테스트 fixture에 넣지 않는다.

## 변경·검증

- 기존 변경을 확인하고 관련 없는 파일 수정·전체 자동 포맷·재구조화를 피한다.
- 프로젝트 설정 후 코드 검사·타입 검사·빌드를 기본 검증으로 둔다. 명령은 실제 구성 뒤 README에 기록.
- 핵심 테스트: 공개/초안 접근, 언어별 공개, 문의 실패·중복·재시도, 코드 저장 왕복·복원, CSS 격리.
- 디자인 검토: 긴 제목·요약 없음·이미지 비율·모바일·확대·포커스.
- 낮은 영향의 단순 변경에 구현을 그대로 반복하는 테스트를 늘리지 않는다.
- 새 블록은 데이터 타입·편집 정의·렌더러·다국어·미리보기·내보내기 영향을 함께 확인.
- 검증 실패·미실행을 정확히 기록. 서비스 기능을 맞춤 구현이 완료된 것처럼 설명하지 않는다.

## Git 변경 이력

- 지침 재작성과 큰 코드 변경은 목적별로 나눠 diff를 검토하고 버전관리한다.
- 커밋 메시지는 변경 목적을 구체적으로 쓴다. 예: `docs: 자유 블록 격리 규칙 정리`, `feat: 프로젝트 분야 필터 추가`.
- 커밋을 요청받으면 이번 작업의 파일만 명시적으로 스테이징하고 검증 후 커밋한다. 푸시는 별도 요청이나 기존 합의에 따른다.
- 사용자 미커밋 변경은 보존한다. 기존 이력 수정·파괴적인 정리·강제 푸시를 임의로 수행하지 않는다.
- 큰 구조 변경은 되돌릴 수 있는 단계로 진행하고 데이터 migration·복구 영향도 기록한다.

## 구현 후 채워야 할 인수 문서

- 실제 실행/빌드/배포 명령, runtime·lockfile·의존성 버전.
- `.env.example`의 변수 이름·용도·서버/클라이언트 구분. 값은 비워둔다.
- 토큰 수정, 페이지·블록 추가, CMS 필드 변경·migration, 언어 추가 예제.
- 백업·복원·내보내기·파일 정리, 알림 장애 대응, 관리자 계정 복구.
- 도메인·서비스 소유권·과금 알림·업데이트 책임.

실제 로컬 골격의 실행 명령·환경변수 이름은 `docs/LOCAL_CMS_SETUP.md`와 `.env.example`을 기준으로 한다. 실제 값은 Git에 넣지 않는다.
